# 选品与市场验证：先证明有人付钱，再建站

> 市场研究的终点不是行业报告，是一页经营决策：卖给谁、优先解决什么场景、核心竞品是谁、不可妥协的指标是什么、利润能否承受获客成本。

## 一、把问题缩小到可检验

不要研究"美国市场大不大"，要研究：

> "【具体人群】在【具体场景】下，是否愿意为一台【具体产品】付【具体价格】？"

问题必须能证伪。能证伪的问题才有验证价值。

## 二、关键词四篮分析（以 Google 为主战场）

| 词类 | 例子 | 承接方式 |
|---|---|---|
| 交易词 | "xxx gifts for him"、"xxx price" | 产品页 / 集合页直接承接 |
| 比较词 | "best xxx gifts 2026"、"xxx vs yyy" | 测评、清单、对比内容 |
| 问题词 | "what to get someone who has everything" | 灵感、教程内容，培育信任 |
| 品牌词 | 自有品牌名 | 后期自然出现，**不作为冷启动目标**（不能用品牌词 ROAS 证明拉新能力） |

操作顺序：
1. Google Trends：选定国家、5 年 + 12 个月两个窗口对比核心词，看趋势与季节峰值（0–100 是归一化指数，不是搜索量）。
2. 关键词工具（Keyword Planner / Ahrefs / Semrush）：导出搜索量区间、竞争、页首出价；记录工具、地区、查询日期——**估算量不是成交量**。
3. 人工读 20 个重点词的搜索结果页：SERP 是商品页还是教程为主？以教程为主就不要强行导向购买页。
4. 输出关键词意图表：关键词 / 国家 / 意图 / 预估 CPC / 页面类型 / 承接 URL / 状态。

**切口判断标准：搜索量稳定 + 购买意图明确 + 竞品内容还没做透。** 三者同时满足才进。

## 三、竞品拆解（20 个 SKU、10 个站、30 条评论起）

分三层看，不只盯着流量最大的品牌：
- **直接竞品**：同产品同人群
- **替代品**：解决同一问题的不同方案
- **心智竞品**：用户决策时最信任的平台（对独立站来说，Amazon 往往是心智竞品——用户真正在比较的是"为什么不直接去 Amazon 买"）

每个竞品记录：价格与折扣、核心主张、卖点顺序、物流时效、退货保修、社交证据、内容合作来源。特别注意**结账前才出现的运费、税费和地区限制**。

小技巧：把竞品首页最上面三句话、产品页最醒目的五张图、评论区最常见的三个疑虑放进同一张表。三小时后你会发现参数差不多，讲的故事完全不同——差异化就从这里找。

## 四、VOC 证据链（用户原话 → 动作 → 验证）

```
用户原话 → 产品能力核验 → 页面承诺 → 渠道创意 → 订单与售后验证
```

- 样本：100–300 条可追溯评论/讨论，保留来源 URL、日期、国家、型号、星级、原文。
- 标签：场景、任务、期待收益、反对理由、决策触发点、差评原因、售后问题。
- AI 只做初步分类与去重，**必须人工抽检 10–20%**（反讽、否定词、型号混淆是重灾区）。
- 统计口径：写"120 条样本中 18 条提到重量"，不许推断"15% 的消费者都认为太重"。
- 每条洞察指定负责人 + 验证指标（如兼容表上线后，相关售前咨询是否下降、加购率是否改善）。

## 五、受众地图（一页纸）

三类典型人群字段：触发事件、目标任务、现有替代方案、最担心的损失、愿意比较的参数、主要信息渠道、购买阻碍、可验证证据。

反面教材："25–45 岁、男性、收入中高"——这种描述无法指导任何经营动作。

访谈纪律：先问"上一次什么时候遇到这个问题、当时怎么解决的、花了多少钱"，不问"你会不会购买我们的产品"——**假设性赞同不等于支付意愿**。

## 六、小流量验证（进放大前的最后一道关）

1. 同样素材与页面，投目标人群 vs 泛人群，比较 CTR 与 CVR——明显高于泛人群，信号才算出现；
2. 信号出现前不加大预算；出现后先小档爬坡，查边际 CPA；
3. 节庆品类注意：区分**季节性峰值**与**真实需求增长**（Trends 的年度对比 + 非节庆月份的留存单量）。

**过关标准**：能回答"卖给谁、凭什么赢、一单剩多少、最坏亏多少"，且每个答案有来源。
